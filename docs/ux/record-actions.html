Proposal

List, detail pane and the action bar

One system-level pattern for a record opened beside its list: its title never moves, and its actions (the main action, icon tools and ⋯ More actions) fit on one line in English, Lithuanian and Russian. Four options, drawn live below at the app's real sizes and measured, and a recommendation: Option B, the title on its own row and an action bar under it.

18 Nov 2026 · build 7070a52 · the running app in EN and RU at 1280 and 375px, every action label measured in Geist 500 14px · text and rules: record-actions.md

1. What goes wrong today

F1 · The title gives way

The record row is flex-wrap-reverse (record-header.tsx:84): when title and actions do not fit, the actions stay on top and the title drops. The pane's alignment with the screen header (-mt-8, lg:-top-4) assumes one line.

F2 · Words are not sized for the room

Labels differ by up to 1.6× between languages, and nothing checks a label against its room. Breakpoint overflow (showFrom) is tuned in English.

F3 · Three places, three looks

An order's actions are in the row, in a body row of outline buttons (stacked full width on a phone) and in ⋯. The SIM card mixes labelled and icon-only. ⋯ is 36px in a record, 44px in a screen header.

F4 · Built separately

Only orders build the row and the list row's ⋯ from one function (historyActions); every other record builds them twice.

2. Four options

All four keep the title in place and use one action model; they differ in where the actions sit and how much they say. Try each one in the playground.

A · Icon toolbar in the title row

As suggested: every action an icon, its name on hover, all on one line.

[←] WE-000010 [🔗][🖨][✍] [⋯] [✕]
  • Identical in every language; fewest pixels; no measuring with fixed caps.
  • Already the SIM card's 🔑, GitHub's and Gmail's toolbars.
  • The main action becomes a symbol; Create confirmation link, Give SIM have no icon people know.
  • No hover on touch: names need a long-press or ⋯.

B · Title row, then an action bar Recommended

Identity alone on row 1; row 2 is the action bar: the main action with its words, the others as icon tools (your suggestion), ⋯ at the end.

[←] WE-000010 [✕] [🔗 Create confirmation link][🖨][✍] [⋯]
  • The title row is the screen header's twin in every language: alignment is fixed by construction.
  • Measured: the main action keeps its words (full or short) in all 45 cases, every tool visible.
  • Icon tools look the same in every language.
  • A second sticky row: ~52px more of a phone's screen.
  • Needs measuring (one ResizeObserver per bar).

C · One row: labelled main, icon tools, ⋯

B's bar squeezed into the title row; it never wraps, collapsing to short words, fewer tools, then an icon main action.

[←] WE-000010 [🔗 Create link][🖨][✍][⋯][✕]
  • One row; title never moves.
  • Words in English on a wide pane.
  • Measured: the main action is an icon in 32 of 45 cases (most LT/RU, every phone): it becomes A, but only in some languages.
  • The same record looks different per language.

D · Sticky action footer

Identity at the top, labelled actions in a bar at the pane's (or phone screen's) bottom.

  • Thumb reach; most room for words.
  • Stacks on the phone's tab bar; far from the title beside a list.
  • Breaks the top-right corner every header uses.

5. The system (Option B)

Rules

  1. Identity never moves. The record row holds only ←, the title and ✕, is exactly --page-header tall and one line: the title is level with the screen title, in every language. Beside a list the title truncates (full title in its tooltip); on a record's page it may take two lines.
  2. The action bar is the next row, one line, never wrapping: the main action (filled, with words), the tools (icon only), ⋯ at the end. Both rows stick; details and badges scroll under them.
  3. Fit by real words, in the language in use, not by breakpoints.
  4. One action model per record kind, read by the row, the list row's ⋯ and later ⌘K.
  5. No body row of record buttons. Part-level actions stay with their part (Give SIM in Assignments, Upload Signed Form, Change status ▾, Edit beside Sizes).
  6. Icon-only needs a vocabulary icon; its name is its accessible name and tooltip (hover, focus, long-press), and ⋯ lists tools by name on touch screens.
  7. Destructive and asking actions: labelled, in ⋯, last after a separator, "…".
  8. ⋯ is 44px in every header and shows only when it holds something.

The collapse ladder

  1. Full words for the main action, every tool (at most 3, 2 on a phone).
  2. Short words for the main action (ShortWords, required when the full words exceed 200px).
  3. Tools into ⋯, the last first, down to none; they head the menu in the bar's order.
  4. Icon-only main action, still filled and first, its words in the tooltip and as its name.

A pure layoutActions(widths, room) picks the step; the bar measures its room with one ResizeObserver and its words once per language.

The action model

export interface RecordAction {
  id: string
  label: string                     // full words: accessible name, tooltip, ⋯ item
  short?: string                    // words for the bar when label is over budget
  icon?: LucideIcon                 // from the vocabulary; none → never icon-only
  place: 'main' | 'tool' | 'menu'
  destructive?: boolean
  asks?: boolean                    // "…", last in ⋯ after a separator
  disabledReason?: string           // shown in its tooltip; the control stays
  run: () => void
  href?: string
}
// ww/lib/order-actions.ts — read by RecordHeader and the list row's ⋯
export function orderActions(o: Order, can: Can, run: OrderRunners): RecordAction[]
