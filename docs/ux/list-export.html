Exporting a list: Employees first

Employees gets Export: choose the employees (the ones ticked, or all the screen shows), the columns, and the format (Excel or CSV), then the file downloads. The parts are shared, in @ppe/ui, so every other list can get the same Export without new code of its own. That roll-out is a separate Baton task.

What you can do

  1. Tick employees. Where Employees is a table (from tablet width), each row has a checkbox and the header has one that ticks every employee the screen shows (the tab and the search apply). Once one is ticked, a bar above the table says how many and offers Export… and Clear selection, the same bar SIM Cards already has for Change Status.
  2. Or don't tick any. Export in the screen's header (in ⋯ on a phone) exports every employee the screen shows.
  3. Choose in the Export sheet:
    • Employees: Selected (n) or All shown (n). Selected is chosen when there is a selection.
    • Columns: checkboxes, with All and None. They start as the columns the screen shows; the rest (first and last name, language, notes, birth date, nationality, sex, added on) can be ticked. You see only the columns your permissions let you read: sizes need See employee sizes; code, notes, language and identity details need See employee profiles.
    • Format: Excel (.xlsx), the default, or CSV.
  4. Export (n) downloads Employees 2026-11-19.xlsx (the screen's name in your language and today's date). Rows come in the screen's sort order; the header row is in your language.

Decisions taken

  • Built in the browser, from what the screen already loaded. The API already leaves out what the reader may not see (employee.Sight), so the file can hold nothing the screen could not show. No new route, and every list can do the same.
  • Not recorded on the Audit log. The file is what the screen shows; copying the table gives the same. If exports of personal data (birth date, nationality) should be recorded, that is a small route and an event (employee.exported, with the count and the columns); it is listed in the roll-out task as a question.
  • Column order is fixed (the order in the sheet). Reordering and remembering the last choice per list are left out for now.
  • Words: Export, Export…, Selected, All shown, Columns, Format, Clear selection. "Export" is already the Audit log's word; the glossary gets an "Export (of a list)" entry.

Proof of completion

  • Screenshots from the running app: the table with ticked rows and the bar; the Export sheet; the phone's ⋯ with Export…; the downloaded .xlsx opened (rendered from the real file) and the CSV.
  • pnpm typecheck, the unit tests for the writers, the selection and the employee columns, and an e2e step that exports and reads the file back.

The same for every list (WARE-44)

Decided in WARE-44. A list loaded page by page (Orders, SIM Cards, Equipment) offers All matching the filters (n): every page matching its tab, filters and sort, fetched when exporting (ExportSheet's matching); ticking works on the page shown. A log read page by page (System's Errors) exports what is loaded. SIM Cards' Change Status bar is the shared SelectionBar. Exports are still not recorded on the Audit log: a file holds only what the screens show, which is not recorded either; recording them stays a possible follow-up. Shared cells: exportMoment (organisation timezone) and exportEuros.

With the shared parts in place, each list adds its columns and the checkbox column:

  • Staff app: Orders, Item Catalogue, Item Sets, SIM Cards, Equipment, an employee's Items given, Replacements.
  • Administration: Users, Roles & permissions, Suppliers, Manage apps, Security's sessions, Errors. The Audit log keeps its own Export (a date range from the API, not the screen's page).
  • Lists that load page by page (Orders, Company Assets) export what is loaded, or ask the API for the rest: decided per list in that task.
