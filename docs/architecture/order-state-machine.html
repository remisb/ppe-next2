Order state machine

The states an order goes through, and the lifecycle of the confirmation link that moves it from ORDERED to GIVEN. Built from internal/domain/order (service.go, confirmation.go); the rules behind each step are in order-service.md, the tables in order-er-diagram.html. The same diagrams in Markdown are order-state-machine.md.

ORDERED and GIVEN are the only stored statuses (a CHECK). Deleted is not a status but deleted_at. Nothing moves an order back from GIVEN, and nothing changes its lines.

Every move to GIVEN runs in one transaction under the order's row lock: the status and given_* fields, the confirmation evidence (employee name and the receipt's document hash), the revocation of the order's other unused links and the order.given event. A partial unique index allows one confirmation with evidence per order, so two concurrent confirmations cannot both succeed.

A link is created only for an ORDERED order (409 otherwise), and creating one revokes the order's earlier unused links, so at most one is usable. Only sha256(token) is stored; the token is shown once. A link to a deleted order, even a used one, answers 410.
