SIM card state machine

The states a SIM card goes through in Company Assets. A card has two facts that change independently (asset-service.md, rule 2): its connection status, which is stored, and where it is and who holds it, which is derived from its open assignment. No action changes one as a side effect of the other: Change Status never moves a card, and giving or returning never changes its status. Each assignment then has a lifecycle of its own, and a signed copy may be added to it. Built from internal/domain/asset (service.go, import.go) and cmd/api/import-sims.go; the rules behind each step are in asset-service.md, the tables in sim-card-er-diagram.html. The same diagrams in Markdown are sim-card-state-machine.md.

connection_status is stored on assets and limited to the three values by a CHECK. There is no final state: write-off is reserved (written_off_at) and not built, and no route deletes a card. The status never stops a card being returned or marked Not Returned; it matters only to Give SIM, which refuses anything but Active (409 ErrNotActive). A card marked Not Returned is usually then blocked: Prepare Blocking Email prepares the provider's email from its mail template, and the user sets Blocked by hand once the provider confirms. A returned blocked card must be unblocked and set Active before it can be given again.

Location is derived, never stored: Office with no open assignment, With Employee with one, Unknown when that one is marked Not Returned with whereabouts UNKNOWN. The holder is the open assignment's employee, in every held state. Only Register Return brings a card back: not an employee leaving, not the Not Returned mark, not Blocked.

Give SIM runs in one transaction with the card locked FOR UPDATE and the employee FOR SHARE, and answers the first check that fails:

CheckAnswer
The card is live404

Refused moves: Give SIM on a held card is 409 ErrAlreadyGiven; Register Return or Mark as Not Returned on a card in the Office is 409 ErrNotGiven; marking a card already marked is 409 ErrAlreadyMarked, so whereabouts cannot be changed (open decision 7). A partial unique index allows one open assignment per card, so two people giving it at once cannot both succeed.

Assignment

An assignment is never deleted, its giving (employee, date, form, hash) never changes, the mark is set once and a returned assignment is closed: the trigger asset_assignments_guard refuses anything else, and ppe_app has no DELETE on the table. A card's earlier assignments are its history; a new giving is a new assignment.
